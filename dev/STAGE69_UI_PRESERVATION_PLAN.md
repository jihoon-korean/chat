# M.chat Stage69 — 기존 UI 보존 및 멀티프로필 통합 기준

상태: 개발 브랜치의 기존 UI와 chat2 테스트 UI를 코드 수준에서 비교한 사전 점검. **아직 통합/배포/실기기 회귀 테스트를 수행하지 않음.**

## 확인된 파일
- 기존 서비스 UI: `index.html` (dev/stage61-chat2-persona-chat에서 읽기만 함). 프로필, 차단하기, 신고하기, 채팅방 나가기, 메시지 입력 관련 코드 존재.
- 기능 검증 UI: `dev/multi-profile-chat2.html`. Stage61~68의 chat2 기능 테스트용.
- 개발 어댑터: `dev/mb61-chat2-adapter.js` (후속 통합 전 계약 확인 필요).

## 보존 원칙
1. 기존 채팅방의 노란 말풍선, 배경, 배치, 상단 프로필 버튼, 더보기 메뉴, 입력창 및 메뉴 동작을 그대로 보존한다.
2. `dev/multi-profile-chat2.html`의 시각 디자인을 `index.html`에 복사하거나 전체 교체하지 않는다.
3. 멀티프로필에 꼭 필요한 프로필 선택/표시/전환만 기존 UI에 최소한으로 추가한다.
4. 기존 채팅방 나가기, 차단, 신고, 프로필 팝업의 동작과 상태 전환을 사전 회귀 테스트 없이 덮어쓰지 않는다.
5. 서버 결제·채팅은 chat2에서만 테스트한다. 운영 Supabase chat과 GitHub main은 수정 금지.
6. 개발 브랜치 `index.html`도 통합 전에 변경 전 UI 기준 화면과 DOM/이벤트 흐름을 점검하고 변경 사항을 분리한다.

## 검증된 기능 (사용자 브라우저 테스트)
- 첫 메시지/재입장 100P 차감 및 중복 차감 방지
- 메시지 전송·조회, 읽음, 전송 시간
- 보내는 사람 자동 하단 스크롤 / 받는 사람 새 메시지 보기
- 최근 대화 순서, 내 메시지 '나:' 미리보기, 미읽음 배지
- 채팅 목록 닉네임과 첫 글자 아이콘 (사용자 확인)
- 채팅방 상단 프로필 표시 (사용자 확인)

## 미검증 / 후속 작업
- 날짜 변경 경계의 날짜 구분선 실제 테스트
- 여러 멀티프로필 사이에서 채팅방 상대·내 프로필이 정확히 연결되는지
- 기존 UI에서 프로필 팝업, 더보기(나가기/차단/신고), 키보드/스크롤, 노란 말풍선 보존
- 기존 UI의 API 호출과 chat2 멀티프로필 서버 함수 간 매핑/권한 차이 분석
- 기존 UI에 기능 이식 전 브랜치 내 복제 페이지 또는 별도 실험 파일에서 검증
- 실제 사진 업로드는 별도 저장소/권한/비용 설계 전 미구현

## 통합 진행 순서
1. 기존 `index.html`의 채팅방 DOM, 이벤트 핸들러, 서버 호출 흐름을 목록화한다.
2. 테스트 페이지의 프로필 선택/채팅방 조회/메시지 송수신 API를 UI와 분리해 매핑한다.
3. 별도 개발 실험 페이지에서 기존 디자인을 보존한 채 프로필 선택과 표시만 연결한다.
4. 두 계정으로 기존 기능 회귀 테스트 후 다른 기능을 단계적으로 연결한다.
5. 명시적 사용자 승인 없이 기존 `index.html` 또는 운영 환경을 교체하지 않는다.
